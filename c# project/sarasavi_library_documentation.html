🧩 Object-Oriented Programming (OOP) Implementation

The system is built using modern C# .NET multi-tiered OOP principles, separating domain models, business logic controllers, data access contexts, and UI views.

🔒 1. Encapsulation
Data Protection

Bundling state variables and functions into classes, keeping data private/protected and providing controlled property getters/setters and business methods.

📁 File Implementations:
  • Models/Borrower.cs: Encapsulates borrower state (UserNumber, Name, NIC, ActiveLoansCount, HasOverdueLoans). Exposes the business method CanBorrow(out string reason) to enforce 5-book limits and overdue blocks inside the class.
  • Models/LoanRecord.cs: Encapsulates loan data and exposes a computed getter property IsOverdue (public bool IsOverdue => Status == "Active" && DateTime.Now > DueDate;).
  • Models/BookTitle.cs & Models/BookCopy.cs: Encapsulates book catalog properties cleanly.
🛡️ 2. Abstraction
Logic Hiding

Exposing simple high-level service interfaces to the UI while hiding complex SQL transactions, DataReader lifecycles, and validation algorithms behind the scenes.

📁 File Implementations:
  • Services/BorrowerService.cs: Hides raw database queries behind clean methods like GetBorrowerDetails(userNumber) and RegisterBorrower().
  • Services/LoanService.cs: Exposes IssueLoan(), hiding multi-step checks (copy status, overdue status, active limit, database transactions).
  • Services/ReturnService.cs: Exposes ProcessReturn(), hiding automated FIFO reservation checking and set-aside notifications.
  • Data/LibraryDbContext.cs: Hides DB connection creation and automatic SQLite fallback behind GetConnection().
🧬 3. Inheritance
Base Classes

Extending framework base classes to inherit fields, layout properties, and event handlers for reusable GUI development.

📁 File Implementations:
  • UI/MainForm.cs: Inherits from System.Windows.Forms.Form (public class MainForm : Form).
  • All View components inherit from System.Windows.Forms.UserControl:
    • UI/Views/DashboardView.cs
    • UI/Views/BookRegistrationView.cs
    • UI/Views/BorrowerRegistrationView.cs
    • UI/Views/LoanCounterView.cs
    • UI/Views/ReturnCounterView.cs
    • UI/Views/InquiryView.cs
🔄 4. Polymorphism
Dynamic Types

Handling derived classes through unified abstract interfaces for maximum flexibility.

📁 File Implementations:
  • Data/LibraryDbContext.cs: GetConnection() returns the abstract DbConnection type, which polymorphically instantiates either MySqlConnection or SqliteConnection depending on database availability.
  • LibraryDbContext.AddParam() accepts abstract DbCommand and handles parameter binding for both MySQL and SQLite commands.
  • UI/MainForm.cs: Swaps different derived UserControl views dynamically into the main interface panel.

📖 Comprehensive Page-by-Page Technical Guide

📊 1. Dashboard Page (DashboardView.cs)
Analytics & Overview

Main Purpose: Provides real-time library operational analytics and quick navigation shortcuts for librarians.

What Happens on the UI:
  • Displays **Total Book Titles** registered in the library.
  • Displays **Available Physical Copies** ready on shelves.
  • Displays **Active Loans** currently checked out by members.
  • Displays **Overdue Loans Count** (books past their 14-day return due date).
⚡ Behind the Scenes (Code Methods & Logic):

Queries BookTitles, BookCopies, and LoanRecords tables via CatalogService.GetDashboardStats().

var (totalTitles, availableCopies, activeLoans, overdueCount) = new CatalogService().GetDashboardStats();
📚 2. Book Registration Page (BookRegistrationView.cs)
Cataloging & Inventory

Main Purpose: Cataloging new book titles and generating physical copy inventory in the library database.

What Happens on the UI:
  • Librarian selects a **Category Code** (C = Computing, F = Fiction, S = Science, M = Management).
  • System auto-generates the **Next Accession Base Code** (e.g. C0001, F0001).
  • Librarian enters **Title**, **Author**, **Publisher**, and specifies **Number of Copies** (between 1 and 10).
  • Optionally checks **"1st Copy Reference Only"** (marking copy -01 as non-borrowable).
  • Clicking **"Register Book & Copies"** creates the title and physical accession copies (e.g. C0001-01, C0001-02).
⚡ Behind the Scenes (Code Methods & Logic):

Calls CatalogService.AddBookTitleWithCopies() using database transactions to insert into BookTitles and BookCopies tables.

bool success = new CatalogService().AddBookTitleWithCopies(title, author, publisher, classCode, copyCount, refOnly, out msg);
👤 3. Borrower Entry Page (BorrowerRegistrationView.cs)
Member Registration

Main Purpose: Registering new library members and displaying active borrower accounts.

What Happens on the UI:
  • Librarian inputs **Name**, **Sex** (Male/Female), **NIC Number**, and **Address**.
  • System verifies NIC uniqueness and auto-assigns a sequential **User Number** starting at M-1001 (e.g. M-1001, M-1002).
  • Displays a DataGridView table of all registered borrowers with registration dates, active loan counts, and overdue status badges.
⚡ Behind the Scenes (Code Methods & Logic):

Executes BorrowerService.RegisterBorrower() and BorrowerService.GetAllBorrowers() to bind data.

bool ok = new BorrowerService().RegisterBorrower(name, sex, nic, address, out userNum, out msg);
🔄 4. Issue Loan Counter Page (LoanCounterView.cs)
Checkout & Rule Enforcement

Main Purpose: Checking out books to members while enforcing all automated library borrowing rules.

What Happens on the UI:
  • Step 1: Member Verification: Enter/Scan User Number (e.g. M-1001). Automated checks run:
    • ✔ **Max 5 Books Limit:** Progress bar shows current active loan count vs 5-book limit.
    • ✔ **Overdue Check:** If member has unreturned overdue books, borrowing is **BLOCKED**.
  • Step 2: Copy Verification: Enter/Scan Accession Code (e.g. C0002-02). Verifies copy is Borrowable and Available.
  • Step 3: Issue Loan: Calculates **14-Day Return Due Date**. Clicking **"Issue Loan"** completes checkout.
⚡ Behind the Scenes (Code Methods & Logic):

Executes BorrowerService.GetBorrowerDetails() and LoanService.IssueLoan() inside a database transaction.

bool issued = new LoanService().IssueLoan(userNumber, accessionCode, out message);
📥 5. Return Counter Page (ReturnCounterView.cs)
Return & FIFO Queue

Main Purpose: Processing returned books and handling automated FIFO reservation queue alerts.

What Happens on the UI:
  • Librarian enters returned Accession Code (e.g. C0002-01) and clicks **"Process Return"**.
  • System marks loan record as Returned (ReturnDate = Today).
  • Automated FIFO Reservation Checking:
    • **No Reservation:** Copy status updates to Available (placed back on public shelf).
    • **Reservation Exists:** Copy status updates to Reserved, reservation is marked Fulfilled, and a **High-Visibility Alert Modal Window** pops up:
      🔔 RESERVED BOOK ALERT: Do not put on public shelf! Place in Reserved Set-Aside Shelf for Member M-1002.
⚡ Behind the Scenes (Code Methods & Logic):

Executes ReturnService.ProcessReturn() to update LoanRecords, ReservationRecords, and BookCopies within a transaction.

bool retOk = new ReturnService().ProcessReturn(copyCode, out msg, out isReserved, out resUserNum);
🔍 6. Catalog Search & Inquiry Page (InquiryView.cs)
Search & Reservations

Main Purpose: Live inventory searching and placing reservations on unavailable books.

What Happens on the UI:
  • Search by Accession Code (e.g. C0001), Title (e.g. Clean Code), or Author (e.g. Robert C. Martin).
  • Displays live status badges: Available [Green], Borrowed [Blue], Reference Only [Yellow], Reserved [Orange].
  • **Place Reservation:** If a book is borrowed/unavailable, librarian can select the title and click **"Place Reservation for Selected Book"** to add member to the FIFO queue.
⚡ Behind the Scenes (Code Methods & Logic):

Queries via CatalogService.GetInventoryItems() and inserts reservations via ReservationService.ReserveTitle().

bool resOk = new ReservationService().ReserveTitle(titleId, userNumber, out resultMessage);
